> benchmarks, method, source, rapira.

Each chart shows the change from the first published run of this benchmark method. That run is the fixed baseline at 0%. A point compares the new build of its run with the new build of the baseline run. The two runs use different instances, so a point includes the difference between two rigs. The measures are capacity in req/s, and p99 latency and RSS at a constant request rate per target. A higher capacity is better. A lower p99 and a lower RSS are better. A point is green for a better build and red for a worse build only when every round gave a pair and the change reaches the noise floor. The noise floor is the largest change of one build between two runs, plus the largest change of the baseline build between the baseline run and the next run. The gRPC p99 has a higher noise floor. Other points are gray. A gap means a measurement is missing. The tooltip includes the baseline value, the measured values of the run, and the paired comparison with the base build of the run. A click opens the pull request, or the commit for a run without one. On a touch screen, a tap shows the tooltip, and a tap on a point opens the run.
